## 2024-05-19 - MarketCard un-memoized in React
**Learning:** Supabase queries dynamically reconstruct object instances, returning entirely new memory references for each row. The `MarketCard` component inside `MarketList.tsx` receives a `market` object generated by a Supabase fetch, but was missing a `React.memo` wrapper. This caused the entire list of potentially hundreds of market cards to needlessly re-render every time the parent `MarketList` re-rendered (e.g., from background polling or simple state updates). Furthermore, a simple `React.memo` without a custom `areEqual` is insufficient because the `market` prop is always a new reference, and `session` prop changes when balances update. To prevent stale UI bugs without losing performance, the `areEqual` comparator must dynamically iterate over `Object.keys(market)` to compare fields and properly deep compare nested arrays like `market.options`.
**Action:** When rendering long lists of components with data directly retrieved from Supabase, always wrap the item component in `React.memo` with a custom `areEqual` comparator. The comparator must manually verify stability of callbacks (e.g. `onBetPlaced`), check `session?.access_token` alongside object identity, and dynamically shallow-compare `Object.keys()` of the data objects while explicitly deep-comparing known array fields.
